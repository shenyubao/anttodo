# 通知配置

每位成员可在 **设置 → 基础配置 → 通知配置** 中，按场景选择是否发送通知，以及通过哪些渠道发送。未单独保存过的场景默认 **全部开启**。

## 通知渠道

| 渠道 | 说明 |
|------|------|
| **系统通知** | 操作系统级通知。Web 端通过浏览器 / Web Push；桌面端对应 macOS 系统通知；后续移动端对应移动端系统通知。 |
| **钉钉通知** | 钉钉企业内部应用的工作通知。仅当当前团队已配置钉钉单点登录时显示；发送时还需在 SSO 配置中填写 **AgentId**，并在钉钉开放平台开通相应权限。 |

离线模式下通知配置为只读，需恢复网络后再修改。

首次开启「系统通知」时，若浏览器尚未授权，会引导申请通知权限并完成 Web Push 订阅。

## 通知场景

| 场景 | 收件人 |
|------|--------|
| 待办-被指派 | 新的指派人 |
| 待办-到期提醒 | 指派人；若无指派人则为任务创建者（与现有提醒规则一致） |
| 待办-有新的评论 | 指派人（评论作者本人除外） |
| 待办-被提及 | 在待办描述或评论中被 `@` 提及的用户 |
| 笔记-被提及 | 在笔记描述或评论中被 `@` 提及的用户 |
| 待办参与者-被添加到待办 | 新被添加为参与者的用户 |
| 待办参与者-标题变更 | 该待办的参与者（操作者本人除外） |
| 待办参与者-状态变更 | 同上 |
| 待办参与者-有新的评论 | 同上（与指派渠道去重；被 `@` 提及时优先发提及类通知） |
| 待办参与者-有新的子任务 | 同上 |
| 待办参与者-子任务状态变更 | 同上 |
| 待办参与者-子任务标题变更 | 同上 |

待办中的 `@` 提及（描述或评论）由「待办-被提及」控制。笔记中的 `@` 提及（描述或评论）由「笔记-被提及」单独控制。

「待办-到期提醒」复用任务上已配置的提醒规则与触发时间，本页只控制到期时是否走系统通知 / 钉钉，不改变提醒规则本身。

钉钉通知以卡片形式展示通知类型、待办或笔记标题以及相关事件信息。到期提醒还会展示截止时间和可用的任务描述；点击卡片底部的「查看待办」或「查看笔记」，可直接打开 AntTodo 中对应的内容。

## 钉钉通知前置条件

要让「钉钉通知」列可用并真正送达，管理员需要：

1. 在团队空间配置 [钉钉单点登录](/企业管理/单点登录)，并填写 **AgentId**。
2. 在钉钉开放平台为同一企业内部应用开通并发布下列权限（详见单点登录文档的「申请权限」）：
   - **`qyapi_get_member`（通讯录成员读权限）**：用于 `getbyunionid`，把登录时的 unionId 解析为企业 `userid`。未开通时钉钉常返回 `60011`，扫码仍可成功，但无法绑定 `userid`，钉钉通知发不出去。
   - 工作通知 / 发送工作通知相关权限：用于实际投递。
3. 将应用可见范围覆盖需要接收通知的成员。
4. 成员使用钉钉扫码登录过 AntTodo，以便建立钉钉身份绑定；开通 `qyapi_get_member` 并重新发布后，需再登录一次以补写 `userid`。

未配置钉钉 SSO 时，设置页只会显示「系统通知」列，并提示配置 SSO 后可使用钉钉渠道。已配置 SSO 但缺少 AgentId 时，钉钉列会禁用并提示补充 AgentId。

## 产品内通知中心

主导航栏的通知铃铛会展示写入产品内的通知记录（指派、评论、提及、参与者相关变更等）。空态文案为「暂无通知」。点击条目可打开对应任务；支持单条已读与全部已读。

系统通知（OS 推送）与铃铛列表相互补充：前者用于即时提醒，后者用于回溯未读事项。
